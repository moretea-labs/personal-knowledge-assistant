# Leafspan for macOS

A native SwiftUI Markdown workspace with optional related-knowledge search. It does not require a web account.

## Authority and boundaries

- Markdown files remain in the original user-selected directory (including iCloud Drive). No import, duplication, or secondary sync mechanism.
- The optional related-knowledge service maintains the cross-source index; Leafspan calls its local HTTP search/read API at 127.0.0.1:3217.
- SilverBullet and Forge are not prerequisites for the editor. No Forge Runtime changes are made.
- Files outside the selected workspace are read-only related-knowledge previews. Original files and their locations are never changed during search.

## Features

- **Native UI design/interaction:** one window, icon rail + file-information pane + Markdown/PDF/Mind Map document region. Top and left share a restrained monochrome native material; rounded low-contrast navigation and animated Edit/Split/Read control use the same type/icon system. Document Outline and Relationships are shown in a user-selectable right inspector (default) or a large temporary Sheet, not small transient Popovers. Source documents and original workflows remain the only data authority.
- Mixed-file folder navigation (Markdown, PDF and other regular files) with Chinese filenames; folders and documents share the same 16pt disclosure and 18pt SF Symbol slots, compact 32pt rows and 16pt nested indentation. The single native toolbar contains context-sensitive Edit/Split/Read, the file actions menu and transient autosave progress. Finder reveal remains in the existing file actions menu. Appearance lives exclusively in the native application Settings window. File names are native single-click buttons (drag begins on the file icon, avoiding gesture contention). Double-click, disclosure, keyboard movement and Return remain supported; only scan/expansion changes update visible rows. Last-opened Markdown safely restores inside the selected workspace; missing files show a visible status and unreadable files retain their retryable path instead of silently leaving a blank page. Materialized iCloud Markdown opens directly; only dataless File Provider placeholders require download, and post-download file stamps are validated before displaying or editing.
- One native titlebar with compact icon-only Edit, Split and Read (⌘1/⌘2/⌘3); one window-owned parsed Markdown snapshot survives view switching, idle editing prepares the preview off the main thread, and long notes without cross-section reference definitions render lazily by heading to reduce first-layout overhead
- Five complete Markdown typography themes: System (native balanced), Paper (airy rounded editorial), Warm (serif long-form), Midnight (dense monospace technical), Graphite (Nulis-inspired modern sans-serif with warm accents). Each changes font family/size, heading proportions, line/paragraph spacing, list/quote/code/table styling and reading column width, not merely colors. **Leafspan > Settings… (⌘,)** exposes Appearance & Typography, with live font-size, line-spacing and reading-width adjustments, persisted across launches and resettable; there is no appearance control in the working toolbar. **Application Appearance is the single light/dark authority for the entire content area:** every reading theme resolves to a light page/dark ink in Light mode and a dark page/light ink in Dark mode, including editor, preview, empty states and the mind-map surface. Theme and adjustments do not change Markdown source.
- Native file management: right-click a vault note, PDF or folder (or use the current-file ellipsis) to **Rename…**, **Move to Folder…**, **Copy to Folder…** or **Move to Trash**. Files/folders can also be dragged directly onto a sidebar folder to move them. Rename/move/copy deny collisions, symlink escapes and recursive folder moves outside the selected workspace. Deletion uses **Finder Trash**, never permanent removal; folders require confirmation. **⌘Delete** works only while the folder tree has keyboard focus and never overrides the editor's text deletion. The active note and last-opened path are repaired after a move/rename.
- Markdown editing keeps native macOS undo/redo/cut/copy semantics. A compact, persistent formatting toolbar can be shown or hidden from the titlebar and provides Heading, Bold, Italic, List, Quote, Link, Code, Table and clipboard-image actions without introducing a second editor. It edits the same Markdown source and keeps native undo/redo. Keyboard shortcuts remain source-safe: **⌘B** bold, **⌘I** italic, **⌘E** inline code, **⌘K** link, **⇧⌘1/2/3** headings, **⇧⌘8** bullet list and **⇧⌘9** task item. Standard **⌘V** still pastes text; when the clipboard contains an image, Leafspan writes a collision-safe PNG into a note-local attachments directory and inserts the relative Markdown image reference at the current selection.
- The Markdown-backed **Mind Map** is a derived view, not a second document format: headings/lists become spatial parent/child nodes with curved connectors, collapse/expand, drag-to-reorder (list-card top/bottom edge) and drag-to-reparent (center drop), keyboard selection, rename, safe leaf deletion, hierarchy promote/demote, zoom, trackpad magnification and **Fit to Window**. Task-list nodes render an actionable checkbox and support Cmd+Return to toggle task completion in the original Markdown line; ordinary nodes remain unchanged. Node edits write back to the same Markdown draft and autosave path. Links in each node's attached Markdown section, including PDF page/selection citations and quote blocks, appear on that node and reopen the exact source anchor. Long map titles use measured multiline card heights (up to five lines) and provide the full text on hover, including under Compact density. Node titles render Markdown inline emphasis; Bold/Italic actions in Node Actions or the context menu (also ⌘B/⌘I with map focus) edit ordinary Markdown markers instead of creating independent node style metadata. Add Child and drag reparenting insert after the target's own safely indented body and before existing children; paragraphs, PDF citations, quotes and fenced code move with their node. Ambiguous unindented content remains protected with an actionable warning. Pending Add Child/Sibling placeholders are rolled back when inline editing is cancelled or the canvas closes, but only if the original draft remains unchanged.
- **One-app development policy:** `~/Applications/Leafspan.app` (`com.moretea.pks.notes`) is the sole install/run target, and `scripts/install-macos.sh` refuses to replace any running PKS/Leafspan app or install alongside older PKS bundles. The former alternate-bundle `run-dev-qa.sh` route is disabled; verify native interaction against the current installed app after safely closing legacy processes. Source-only `swift build` and `swift test` remain available without launching an app.
- **Mind Map style presets:** choose Classic, Colorful (stable branch accents and colored curved connectors), or Minimal (serif node typography and orthogonal links) directly from the map toolbar. One global view-only style preference and a Compact / Standard / Spacious node-spacing setting are remembered across app launches; both update the live layout and PNG/PDF exports without touching Markdown. Card geometry is remeasured with the selected font design whenever style or density changes; all presets preserve the same Markdown writer and support dark/light appearance. PNG/PDF exports reuse the selected card and connector style, with a clean light export background. OPML/MindNode import/export remains hierarchy-only; this app preference is not embedded in Markdown or MindNode packages.
- **Mind map authoring / MindNode interoperability:** The titlebar More menu has **New Mind Map** for direct creation in the current folder; empty Markdown notes also offer **Create Mind Map**; Tab adds a child, Return adds a sibling, and new nodes immediately enter inline editing (Return/checkmark saves, Escape/cross cancels); context-click a list branch to delete its complete subtree only after confirmation, while attached prose/code is protected; double-click edits an existing node. The toolbar imports native .mindnode packages, imports/exports **OPML**, and exports full-map **PNG/PDF** through native macOS panels (including collapsed descendants, without transient selection or inline-editor UI). Native import copies only visible title hierarchy into a NEW Markdown note; style, positions, images, notes, tasks and cross-connections remain intentionally outside the Markdown authority. Real-library validation on MindNode 2026.7.1 covered all 36 existing user packages: schema versions **7 and 9**, including historical files with untitled structural nodes; **36/36 imported successfully**. Native export clones a user-selected real v7/v9 template into a NEW package, rejects existing destinations and Markdown it cannot preserve, strips unrelated template resources/previews, stages output before a no-overwrite move, and never modifies the source template. Real v9 (147-node) and v7 (8-node) import-export-import round-trips were exact; generated packages were handed to the installed MindNode 2026.7.1 application without document-format/open errors. OPML remains the portable fallback for richer or unknown future schemas.

- Navigation now includes workspace-scoped **Recent** notes and persistent **Favorites** (lightweight path metadata only, never a second content store). Quick Open keeps the picker open and refreshes its single vault index once if the user selects a cached path that has since disappeared. A titlebar **Document Outline** derives ATX headings from the same fenced-code-aware parser used by Markdown preview sectioning; choosing a heading focuses the native editor at the correct UTF-16 offset.
- **V1 document model is deliberately single-window.** Quick Open, Recent, Favorites, search results and links all switch the one active NotesModel document after the existing Save/Discard/Cancel guard. Custom tabs or multiple editable windows are intentionally not layered over the same model because that would create competing draft/save state; a future multi-window feature must first give each window its own explicit document authority.
- The Relationships control shows three derived views without a second graph database: **Outgoing** Markdown/Wiki links, lazy **Backlinks** from the current workspace, and lazy **Related · Library** results from the related-knowledge index, queried using the current note's content rather than its filename alone and filtered for multiple matching content signals. Relationship rows wrap long titles and excerpts inside the scrollable popover instead of truncating them. Preview and Relationships both use the same file/link resolver for note, Markdown heading and PDF anchors. When a Markdown file is renamed or moved, its own locally available relative note/PDF references are conservatively rebased to canonical vault paths before loading the new file; unreadable/cloud-only contents and other notes are not rewritten, and unresolved incoming links are explicitly reported. A broken outgoing reference can be explicitly retargeted using the existing Quick Open picker; only matching targets in the active Markdown draft are rewritten (labels, image embeds and fenced examples remain intact). Cloud-only backlink scans show incomplete coverage and offer user-initiated batches of at most six downloads, never automatic full-vault hydration.
- **Double-click a rendered Markdown preview to Edit**; use **⌘Return** to toggle Edit/Read in both directions. In Edit, double-click the blank page margin to Read, while a normal double-click on text retains native word selection. Existing ⌘1/⌘2/⌘3 reading modes still work and no extra toolbar was added.
- PDF page references encode Markdown-special filename characters (including parentheses and square brackets) while preserving readable labels; direct page jumps report out-of-range numbers without silently moving to another page. Rapid PDF switching propagates cancellation to detached loading and suppresses stale deferred fit-width layout from the prior document.
- Native read-only PDFKit preview with zoom and text selection; other files use macOS default applications. PDF search reports explicit no-match results only after a completed query; changing the query or source PDF cancels stale search publication and clears previous highlights. Source selection anchors round-trip through the same PDFKit reader.
- In-workspace Markdown links and images, with path containment checks
- Related-knowledge search across indexed sources; view snippets and read out-of-workspace results without editing them
- Search result source labels with per-result ellipsis/right-click actions; Finder reveal, default app open, and path copy for local/managed files
- Duplicate related-knowledge chunks are grouped per document while preserving ranked order; expand to see every matching section and its excerpt
- Search title/summary keywords are highlighted; click a match section to scroll the Markdown preview to its heading (or first matching heading section) without changing the source file
- Web-source browser/open-link actions; opaque URI fallback copies the source identifier without guessing a file path
- The note tree and title-bar ellipsis menu offer contextual file actions; missing files report a non-destructive error
- Debounced local Markdown autosave after 650 ms of inactivity, and immediate flush on note switch / quit. Saving shows only a small toolbar progress indicator. An external-edit conflict preserves the draft and retains native Save / Discard / Cancel protection before leaving
- ⌘P opens the existing native Quick Open palette; ⌘N or the sidebar New Note button **immediately creates a blank, focused editor**, generating collision-safe `Untitled.md`, `Untitled 2.md`, etc. without asking for a filename. The first typed content is saved by the existing autosave writer. ⌘F focuses Library Search, ⌘O selects the existing workspace, and folder right-click creates a blank note there.
- Markdown loads and preview parsing run off main actor; only changed Split drafts are debounced (~260 ms), already-parsed content survives view/theme changes, and canceled stale tasks cannot replace newer drafts
- Cmd+S is still available for immediate saves; no persistent Save button or success banner, and concurrent external edits are checked before every write
- Create notes beside the selected note (or at the workspace root), or explicitly inside a folder via its context menu; destinations are validated in-vault and exclusive file creation prevents overwrites. Empty new notes are already real `.md` files, so quit/switch never risks losing an in-memory-only unsaved note.

## Native design reference

The **Graphite** style follows [Nulis Notes Desktop Dark](https://dribbble.com/shots/19751267-Nulis-Notes-Desktop-App-Dark) by Rayfan Tio Saputro / Keitoto: charcoal editor canvas, darker navigation surface, editorial sans serif typography, restrained warm emphasis, simple macOS titlebar. The companion [Nulis light design](https://dribbble.com/shots/19726217-Nulis-Notes-Desktop-App) is a reference for light/dark consistency. The older light style is retained as another selectable preset. The second comparison is [Equal Desktop Notes App](https://dribbble.com/shots/24205265-Desktop-Notes-App) for text hierarchy. The earlier Bear/Panda light direction was explicitly rejected by user feedback. For Markdown and file-tree behavior, compare the open-source [MiaoYan](https://github.com/tw93/MiaoYan). This is an original SwiftUI implementation with the existing Leafspan source/renderer; no third-party brand assets, UI code or theme packages are imported.

Other UI research indexes: [Dribbble macOS UI](https://dribbble.com/search/macos-app-ui), [Mobbin](https://mobbin.com/), and [Collect UI](https://collectui.com/designs/mac-app-ui-design-inspiration) (this category currently has no designs to copy). Prefer shipped native product screenshots over unrelated dashboard or task manager mockups.

## Development and installation

Requires macOS 14 or later with Swift/Xcode.

    cd integrations/pks-notes-macos
    swift test --jobs 4
    # Use the committed AppIcon.icns; do not regenerate the brand mark during UI work.
    swift build -c release --jobs 4
    ./scripts/install-macos.sh
    open "$HOME/Applications/Leafspan.app"

For native GUI acceptance, use only the installed `~/Applications/Leafspan.app` and its original bundle identity. Verify any previous QA/acceptance process has exited safely and retire legacy bundles only after owner/data checks. `scripts/run-dev-qa.sh` explicitly refuses separate app creation; build/test without launching, then use the guarded canonical installer. Existing PDF/Markdown test fixtures and file anchors are test data, not alternate app identities. Do not relax the real PDF source-anchor/selection GUI acceptance requirements.

**First launch:** select the existing iCloud Drive folder `学习笔记管理` using **Choose Folder** in the toolbar ellipsis menu and click **Open** in the macOS folder picker. This is a one-time macOS file-access grant for this application, not a login and not a new sync service. The app retains the system security-scoped folder bookmark and reopens the same folder on subsequent launches. Until permission is granted, the notes tree and workspace-local search remain empty; optional related-knowledge search may still return read-only external results.

The canonical folder is `~/Library/Mobile Documents/com~apple~CloudDocs/学习笔记管理`. No source files are imported, relocated or copied. iCloud Drive handles synchronization. Do not bypass the native folder picker by writing the folder path to app preferences: that does not grant macOS permissions.

The app bundle copies `Resources/AppIcon.icns` into `Contents/Resources` and declares `CFBundleIconFile=AppIcon`; the icon generator uses AppKit only (no external icon dependency).

## Verification

The Swift tests cover workspace-local filename/body search without a service, optional cross-source results, cancellation, Chinese decoding, mixed-file browsing, PDF navigation, autosave/external-write safety, traversal protection and Markdown links. The optional local related-knowledge service is never required for workspace Search. Native GUI acceptance must still be verified separately.

The app does not implement remote access or its own synchronization. Large or not-yet-downloaded iCloud items can still take time to open. Avoid simultaneous edits from multiple applications.
